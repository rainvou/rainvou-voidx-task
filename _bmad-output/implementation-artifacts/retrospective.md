## 잘 된 점 (Keep)

### 1. 병렬 에이전트 실행 전략
- 3차 배치로 나누어 독립 Task를 worktree 격리 환경에서 병렬 실행
- 1차: Task 2+3+4 (인증/프로젝트/워크플로우) → 동시 완료
- 2차: Task 5+6, 9+10, 11+12 (Core/칸반/Git) → 동시 완료
- 3차: Task 14+15, 16+17+18, 19+20+21+22 (AI/협업/대시보드+API) → 동시 완료
- **병렬화로 순차 실행 대비 약 3배 속도 향상**

### 2. BMAD → 구현 파이프라인
- 브레인스토밍 78개 아이디어 → Product Brief → PRD → Architecture → Epics → 구현
- 체계적 요구사항 추적: Vision → Criteria → Journey → FR → Story → Code
- PRD 검증 PASS 후 구현 진입으로 재작업 최소화

### 3. 테스트 커버리지
- 모든 Task에 유닛 테스트 포함 (161개)
- 순수 함수 분리 (taskKeyParser, dashboardUtils, kanban utils)로 테스트 용이성 확보
- Prisma 의존 코드와 순수 로직 분리 패턴 확립

### 4. 기술 스택 결정의 일관성

## 개선할 점 (Improve)

### 1. Cherry-pick 충돌 관리
- 병렬 에이전트가 같은 파일 (router.ts, init.ts)을 생성하여 머지 충돌 빈발
- **교훈:** 공유 파일 (라우터, 설정)은 기반 Task에서 먼저 생성하고, 병렬 에이전트에게는 자기 파일만 생성하도록 지시

### 2. Prisma 7.x 호환성
- 생성된 코드가 Prisma 7.x의 새 import 경로(`/client`)와 어댑터 요구사항을 반영하지 못함
- **교훈:** 프로젝트 초기화 Task에서 Prisma generate + 실제 import 테스트까지 포함해야 함

### 3. 루트 페이지 미구현
- Next.js 기본 템플릿이 남아있어 로그인 후 빈 화면 표시
- **교훈:** UI 프로젝트에서 "로그인 후 랜딩 페이지"를 별도 Task로 명시적 포함

### 4. 일부 Task의 실제 파일 누락
- worktree에서 cherry-pick 시 빈 커밋이 되는 경우 발생 (Task 19-22)
- **교훈:** cherry-pick 후 git diff --stat으로 파일 수 검증 자동화 필요
